# 📡 IPv4 Price Aggregator

Мониторинг цен на блоки IPv4: **актуальные цены аренды** из публичного
рыночного API и **рыночные цены покупки** по регионам
RIR, с историей, графиками и интерфейсом на 6 языках
(английский, украинский, русский, португальский, немецкий, французский).

Три варианта программы работают с **одной базой SQLite** — можно запускать
их в любой комбинации, история накапливается в одном месте:

| Вариант | Стек | Что делает | Сохраняет данные? |
|---|---|---|---|
| **1. Python-дашборд** | Python + Streamlit | Полноценный дашборд: живые таблицы, покупка по регионам, графики истории | Да → SQLite |
| **2. Локальный веб-вариант (Node.js)** | Node ≥ 22.5, ноль npm-зависимостей | Собирает данные каждые 5 минут **в фоне** (браузер не нужен) + та же веб-морда | Да → SQLite |
| **3. GitHub Pages** | Статический HTML/JS, бесплатный хостинг | Чисто сессионный мониторинг: значения + графики только пока страница открыта | Нет |

🌐 Языки интерфейса: в Python-дашборде селектор языка находится в сайдбаре;
в веб-вариантах — в шапке. Выбор запоминается.

## 1. Python-дашборд (Streamlit)

### Требования
- Python ≥ 3.10

### Установка и запуск
```bash
cd ipv4_aggregator
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
Откройте http://localhost:8501. В дашборде четыре вкладки: живые цены
аренды (живой API цен), цены покупки по регионам, история и графики, «о проекте».

- **Auto-refresh** (галочка в сайдбаре) перерисовывает вкладку живых цен
  каждые 5 минут; каждое успешное обновление сохраняется в SQLite.
- Кнопка **Refresh now** принудительно выполняет новый запрос.
- Фильтры по региону и размеру блока влияют на таблицы и графики.

### Выход
Просто `Ctrl+C` в терминале. Каждый snapshot (снимок данных) фиксируется
в SQLite сразу после успешного запроса, поэтому ничего не теряется;
соединения закрываются, WAL-файлы не остаются.

## 2. Локальный веб-вариант (Node.js)

### Требования
- **Node.js ≥ 22.5** (ради встроенного модуля `node:sqlite`). Проверить:
  `node --version`. `npm install` не нужен — зависимостей **ноль**.

### Запуск
```bash
node server.js
# или: npm start
```
Откройте **http://localhost:8787**.

Что он делает:
- Сразу при старте и затем каждые **5 минут** запрашивает цены аренды из
  рыночного API и пишет snapshot в общую базу `ipv4_prices.db`
  (строки помечаются `writer='node'`). Браузер держать открытым **не**
  нужно — сбор идёт в фоне.
- Раздаёт веб-интерфейс из `docs/` (та же страница, что и в варианте
  GitHub Pages, но в режиме «локальный сервер» — с полной историей из базы).
- JSON API:
  - `GET /api/config` → режим, версия, интервал, время последнего обновления;
  - `GET /api/history?block=/24&days=7&limit=2000` → строки истории;
  - `GET /api/quotes` → свежий запрос всех 9 блоков на стороне сервера.

### Настройка (переменные окружения)
| Переменная | По умолчанию | Значение |
|---|---|---|
| `PORT` | `8787` | HTTP-порт |
| `LARUS_LOCATION` | `US` | Локация, передаваемая в API цен (`US`, `EU`) |

### Выход
`Ctrl+C` или `kill <pid>` (SIGTERM): таймер сбора останавливается,
HTTP-сервер закрывается, база закрывается с WAL checkpoint, код выхода 0.
Двойное `Ctrl+C` безопасно. Убийство процесса посреди записи не может
повредить базу — SQLite откатит транзакцию при следующем открытии.

## 3. GitHub Pages (статический мониторинг)

Статический вариант лежит в [`docs/`](docs/) и показывает живые цены +
графики **только пока страница открыта** (одна точка каждые 5 минут,
только в памяти). Без сервера, без базы, бесплатный хостинг.

### Настройка
1. Запушьте этот репозиторий на GitHub.
2. Репозиторий → **Settings** → **Pages**.
3. **Source**: *Deploy from a branch* → ветка `main`, папка **`/docs`** → Save.
4. Через минуту сайт доступен по адресу `https://<username>.github.io/<repo>/`.

И всё — ни шага сборки, ни GitHub Actions workflow.

## Общее хранилище (как уживаются два писателя)

И Python-дашборд, и Node-сервер пишут в одну и ту же базу `ipv4_prices.db`
в корне проекта:

- **WAL mode** — режим журналирования с упреждающей записью
  (`PRAGMA journal_mode=WAL`) + `busy_timeout=5000` позволяют обеим
  программам писать одновременно без ошибок вида «database is locked».
  Запускайте обе хоть неделями — строки от обоих писателей
  (`writer='python'` / `writer='node'`) попадают в одну таблицу и вместе
  показываются в истории.
- Каждый snapshot — одна атомарная транзакция: прерванная запись
  откатывается автоматически.
- Пока запущена хотя бы одна из программ, вы можете видеть файлы
  `ipv4_prices.db-wal` / `ipv4_prices.db-shm` — это нормально; после
  корректного выхода они исчезают. WAL не работает на сетевых шарах
  (NFS/SMB): держите проект на локальном диске.
- Файл базы **не** коммитится в репозиторий (см. `.gitignore`); он
  создаётся автоматически при первом запуске.

## CORS (вариант GitHub Pages)

Браузер на GitHub Pages обращается к API цен напрямую. Это работает,
потому что API возвращает `access-control-allow-origin: *` — проверено
**20.09.2026** командой (`PRICE_API_URL` — адрес API цен):

```bash
curl -sS -D - -o /dev/null -H "Origin: https://<username>.github.io" "<PRICE_API_URL>"
```

Если API когда-нибудь уберёт этот заголовок, на странице появится
предупреждающий баннер. Обходной путь: задать публичный CORS-прокси с правами
только на чтение в консоли браузера:

```js
localStorage.setItem("ipv4agg.proxy", "https://corsproxy.io/?");
// очистить: localStorage.removeItem("ipv4agg.proxy")
```

Нюансы: третья сторона видит URL запросов, действуют лимиты запросов,
ответы могут кэшироваться. Локальному Node-варианту прокси никогда не нужен.

## Решение проблем

| Проблема | Решение |
|---|---|
| `database is locked` | Подождите 5 с — писатели повторяют попытку автоматически (busy_timeout). Если не проходит, не держите проект на сетевой шаре. |
| `node:sqlite` отсутствует | Ваш Node < 22.5 — обновите Node. |
| Графики пустые на GitHub Pages, показан предупреждающий баннер | Проблема с CORS или сетью — см. раздел про CORS выше. |
| Вместо графиков простой текст | CDN с Chart.js был недоступен; графики вернутся, когда он ответит. |
| История пустая | Данные появятся после нескольких успешных обновлений (или дайте `server.js` поработать несколько минут). |

## Источники данных

- **Аренда (живые)**: публичное рыночное API — тарифы
  CAPACITY_ONLY и CONTINUITY_PRODUCTION, /24…/16, USD.
- **Покупка**: ручные рыночные снимки (отчёты IPv4Center / IPv4.Global)
  по регионам RIR, в `data_sources.py`.
