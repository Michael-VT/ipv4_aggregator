# 📡 IPv4 Price Aggregator

Моніторинг цін на блоки IPv4: **ціни на оренду в реальному часі** з публічного
ринкового API та **ринкові ціни купівлі** за регіонами RIR,
з історією, графіками та інтерфейсом шістьма мовами
(англійська, українська, російська, португальська, німецька, французька).

Три варіанти програми працюють з **одною спільною базою SQLite** — запускайте
їх у будь-якій комбінації, історія накопичується в одному місці:

| Варіант | Стек | Що робить | Зберігає дані? |
|---|---|---|---|
| **1. Python-дашборд** | Python + Streamlit | Повноцінний дашборд: таблиці в реальному часі, купівля за регіонами, графіки історії | Так → SQLite |
| **2. Локальний веб (Node.js)** | Node ≥ 22.5, жодної npm-залежності | Збирає дані кожні 5 хв **у фоновому режимі** (браузер не потрібен) + та сама веб-сторінка | Так → SQLite |
| **3. GitHub Pages** | Статичні HTML/JS, безкоштовний хостинг | Суто сеансовий моніторинг: значення + графіки лише поки сторінка відкрита | Ні |

🌐 Мови інтерфейсу: у Python-дашборді перемикач мови розташований у бічній
панелі; у веб-варіантах — у шапці сторінки. Вибір запам'ятовується.

## 1. Python-дашборд (Streamlit)

### Вимоги
- Python ≥ 3.10

### Встановлення та запуск
```bash
cd ipv4_aggregator
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
Відкрийте http://localhost:8501. Дашборд має чотири вкладки: ціни оренди в
реальному часі, ціни купівлі за регіонами, історія та графіки, і
«про проєкт».

- **Автооновлення** (прапорець у бічній панелі) щоп'яти хвилин перемальовує
  вкладку з даними в реальному часі; кожне успішне оновлення зберігається в SQLite.
- Кнопка **Оновити зараз** примусово виконує нове отримання даних.
- Фільтри за регіоном і розміром блоку впливають і на таблиці, і на графіки.

### Завершення роботи
Просто `Ctrl+C` у терміналі. Кожен snapshot (знімок даних) записується в SQLite
одразу після успішного отримання, тож дані не губляться ніколи; з'єднання
закриваються, WAL-файли не залишаються.

## 2. Локальний веб-варіант (Node.js)

### Вимоги
- **Node.js ≥ 22.5** (заради вбудованого модуля `node:sqlite`). Перевірте:
  `node --version`. `npm install` не потрібен — залежностей **немає жодної**.

### Запуск
```bash
node server.js
# or: npm start
```
Відкрийте **http://localhost:8787**.

Що він робить:
- Одразу після старту, а далі кожні **5 хвилин** отримує ціни оренди з живого
  API цін і
  записує snapshot до спільної бази `ipv4_prices.db` (рядки позначаються
  `writer='node'`). Браузер тримати відкритим **не** потрібно — збір даних
  працює у фоновому режимі.
- Роздає веб-інтерфейс із каталогу `docs/` (та сама сторінка, що й варіант
  GitHub Pages, але в режимі «локального сервера» з повною історією з бази).
- JSON API:
  - `GET /api/config` → режим, версія, інтервал, час останнього оновлення;
  - `GET /api/history?block=/24&days=7&limit=2000` → рядки історії;
  - `GET /api/quotes` → свіже отримання всіх 9 блоків на боці сервера.

### Налаштування (змінні середовища)
| Змінна | Типово | Значення |
|---|---|---|
| `PORT` | `8787` | HTTP-порт |
| `LARUS_LOCATION` | `US` | Локація, що передається до API цін (`US`, `EU`) |

### Завершення роботи
`Ctrl+C` або `kill <pid>` (SIGTERM): таймер збору даних зупиняється, HTTP-сервер
закривається, база закривається з WAL checkpoint, код виходу — 0. Подвійне
`Ctrl+C` безпечне. Примусове завершення посеред запису не може пошкодити базу —
SQLite відкотить транзакцію під час наступного відкриття.

## 3. GitHub Pages (статичний моніторинг)

Статичний варіант лежить у [`docs/`](docs/) і показує ціни в реальному часі та
графіки **лише поки сторінка відкрита** (одна точка кожні 5 хвилин, тільки в
пам'яті). Без сервера, без бази даних, безкоштовний хостинг.

### Налаштування
1. Запуште цей репозиторій на GitHub.
2. Репозиторій → **Settings** → **Pages**.
3. **Source**: *Deploy from a branch* → гілка `main`, каталог **`/docs`** → Save.
4. За хвилину сайт буде доступний за адресою `https://<username>.github.io/<repo>/`.

Це все — ні кроку збірки, ні workflow в GitHub Actions.

## Спільне сховище (як уживаються два writer-и)

І Python-дашборд, і Node-сервер пишуть до однієї бази `ipv4_prices.db` у корені
проєкту:

- **WAL mode** (`PRAGMA journal_mode=WAL`) + `busy_timeout=5000` дають обом
  програмам змогу писати одночасно без помилок «database is locked». Тримайте
  обидві тижнями — рядки від обох writer-ів (`writer='python'` /
  `writer='node'`) потрапляють до однієї таблиці й разом показуються в історії.
- Кожен snapshot — це одна атомарна транзакція: перерваний запис відкочується
  автоматично.
- Поки працює хоча б одна з програм, поруч можуть з'являтися файли
  `ipv4_prices.db-wal` / `ipv4_prices.db-shm` — це нормально; після коректного
  завершення вони зникають. WAL не працює на мережевих ресурсах (NFS/SMB):
  тримайте проєкт на локальному диску.
- Файл бази **не** комітиться до репозиторію (див. `.gitignore`); він
  створюється автоматично під час першого запуску.

## CORS (варіант GitHub Pages)

Браузер на GitHub Pages звертається до API цін напряму. Це працює, бо API
повертає заголовок `access-control-allow-origin: *` — перевірено
**2026-09-20** такою командою:

```bash
curl -sS -D - -o /dev/null -H "Origin: https://<username>.github.io" \
  "<PRICE_API_URL>"
```

(де `PRICE_API_URL` — адреса API цін). Якщо API колись прибере цей заголовок,
сторінка покаже попереджувальний
банер. Запасний варіант: пропишіть публічний CORS-проксі (лише читання) в
консолі браузера:

```js
localStorage.setItem("ipv4agg.proxy", "https://corsproxy.io/?");
// clear: localStorage.removeItem("ipv4agg.proxy")
```

Застереження: третя сторона бачитиме URL запитів, діють обмеження на частоту
запитів, відповіді можуть кешуватися. Локальному Node-варіанту проксі не
потрібен ніколи.

## Усунення несправностей

| Проблема | Розв'язання |
|---|---|
| `database is locked` | Зачекайте 5 с — writer-и повторюють спроби автоматично (busy_timeout). Якщо не минає, не тримайте проєкт на мережевому ресурсі. |
| Відсутній `node:sqlite` | У вас Node < 22.5 — оновіть Node. |
| Порожні графіки на GitHub Pages, показано попереджувальний банер | Проблема з CORS або мережею — див. розділ про CORS вище. |
| Графіки замінено простим текстом | CDN із Chart.js був недоступний; графіки повернуться, коли він запрацює. |
| Історія порожня | Дані з'являться після кількох успішних оновлень (або дайте `server.js` попрацювати кілька хвилин). |

## Джерела даних

- **Оренда (у реальному часі)**: публічне ринкове API — плани
  CAPACITY_ONLY та CONTINUITY_PRODUCTION, /24…/16, у доларах США.
- **Купівля**: ручні ринкові snapshot-и (звіти IPv4Center / IPv4.Global) за
  регіонами RIR, у файлі `data_sources.py`.
